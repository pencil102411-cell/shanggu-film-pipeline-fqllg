# Blender 灰模预演

把**平面图 + 分镜**变成一条灰模预演视频，交给 Seedance 2.5 当参考。视频只负责锁定四件事：

1. 场景的真实尺寸和空间结构
2. 人物站在哪、怎么走、朝哪
3. 镜头的构图、焦段、机位高度和运镜
4. 切镜的时间点和节奏

人物形象、建筑细节、材质、光影、肢体动作**都不管**，这些以用户最终写给 Seedance 的提示词为准。人物一律用**无四肢的彩色人偶**：身体是角色的颜色，头部浅色一面是脸、深色一面是后脑，让 Seedance 看清人物朝向（详见站位表）。

## 核心做法

Agent 写三张 JSON 参数表 → 运行 `previs.py` → 脚本在后台调用 Blender 搭场景、摆人、架相机、逐帧烘焙动画、自动检查、渲染，再用 FFmpeg 合成视频。

- **参数表是唯一依据**。所有修改先改参数表再重新生成，不在 Blender 里手动改完就算数。
- **每次生成都新建版本文件夹**（`output/v01_scene`、`v02_blocking`……），旧版本永不覆盖。
- **默认画幅 21:9，1470×630**（Seedance 2.5 的 21:9 原生尺寸），24 帧/秒，无声。预览用 700×300。

| 参数表 | 内容 | 详细写法 |
|---|---|---|
| `spec/scene.json` | 墙、门窗洞、地台、台阶、柱子、家具……（米） | [references/场景表.md](references/场景表.md) |
| `spec/blocking.json` | 人物颜色、身高、每个时间点的位置/朝向/姿态 | [references/站位表.md](references/站位表.md) |
| `spec/shots.json` | 每个镜头的起止时间、机位、焦段、运镜 | [references/镜头表.md](references/镜头表.md) |

运镜和剪辑的规则见 [references/运镜与剪辑规则.md](references/运镜与剪辑规则.md)。交付规范见 [references/Seedance交付规范.md](references/Seedance交付规范.md)。遇到报错先查 [references/踩坑记录.md](references/踩坑记录.md)。

## 命令

`<技能目录>` 指本 SKILL.md 所在的文件夹。用 `python -B` 运行，避免在技能目录里写缓存文件。

```
python -B "<技能目录>/scripts/previs.py" setup                    # 首次：找 Blender/FFmpeg 并实测渲染
python -B "<技能目录>/scripts/previs.py" init      <项目目录>       # 新建项目文件夹
python -B "<技能目录>/scripts/previs.py" plan-grid <项目目录> [--crop X0 Y0 X1 Y1]   # 平面图加米制网格
python -B "<技能目录>/scripts/previs.py" scene     <项目目录> [--tag 说明]   # 建灰模
python -B "<技能目录>/scripts/previs.py" blocking  <项目目录> [--tag 说明]   # + 人物走位
python -B "<技能目录>/scripts/previs.py" preview   <项目目录> [--tag 说明]   # + 镜头，低清预览
python -B "<技能目录>/scripts/previs.py" final     <项目目录> [--tag 说明] [--empty] [--per-shot]
python -B "<技能目录>/scripts/previs.py" open      <项目目录> [版本名]      # 在 Blender 窗口里打开
```

每条命令最后一行会打印 `RESULT_DIR=<版本文件夹>`。出错时打印 `错误：……`，原因写的是白话，按提示改参数表即可。完整日志在版本文件夹的 `blender_log.txt`。

首次使用先跑 `setup`。它会把 Blender、FFmpeg 的路径记到 `~/.blender-greybox-previs/config.json`。找不到时用 `setup --blender <路径> --ffmpeg <路径> --ffprobe <路径>` 指定。还依赖 Python 3.9+ 和 Pillow（`python -m pip install pillow`）。

## 工作流程：6 步，3 道确认

**每道确认都要停下来等用户点头再往下走。** 给用户看的东西：图片直接展示（或给出路径），表格用白话写。

### 第 1 步：收资料（缺什么就主动要）

| 资料 | 必需？ | 没有时怎么办 |
|---|---|---|
| 平面图（场景俯视布局） | **必需** | 主动向用户要。不能凭空猜空间结构 |
| 至少一个已知尺寸（比例尺 / 标注 / 房间宽度 / 门宽） | **必需** | 先问；实在没有，用常规门宽 0.9 米等推测，并标"推测" |
| 分镜脚本或镜头描述 | **必需**（到第 4 步时） | 主动要；也可以先把空间建出来 |
| 层高、门窗高度、台阶级数、楼层 | 最好有 | 用 [默认尺寸表](references/场景表.md#默认尺寸表) 并标"推测"，古建/宫殿必须问 |
| 人物名单、身高、颜色偏好 | 最好有 | 默认男 1.78 米、女 1.65 米，颜色按 蓝/红/黄/绿/紫/橙 依次分配 |
| 效果图、正反打参考图 | 可选 | 用来估高度和体量 |

项目文件夹：用户指定的位置；总调度的项目模式下（能找到这场的 `进度表.md`，找法见下文「和总调度的配合」）用这场的 `02_预演/`；都没有就在当前工作目录下建 `<场景名>_灰模预演`。运行 `init`，把用户给的图片复制到 `input/`。

### 第 2 步：读平面图 → 《空间尺寸清单》 → **确认①**

1. 看平面图，确定比例：找到一个已知尺寸，量出它在图上的像素长度，写进 `scene.json` 的 `plan`（`px_per_m` + `origin_px`，或两点标定 `calib`）。
2. 运行 `plan-grid`，打开生成的 `平面图_米制网格.png` 读坐标；细节处用 `--crop` 放大。**坐标从网格图上读，不要凭感觉估。**
3. 按 [templates/空间尺寸清单模板.md](templates/空间尺寸清单模板.md) 写一份清单给用户：各区域长宽、层高、墙厚、门窗位置和尺寸、台阶、柱子、主要家具。推测的数值标"推测"。
4. 用户确认或修正后，再写 `scene.json`。

### 第 3 步：建灰模 → **确认②**

运行 `scene`。**先自己看一遍**输出图，确认没有明显错误，再给用户看：

- `俯视叠平面图.png`：灰模俯视图半透明叠在平面图上。墙和家具应该与平面图重合
- `俯视图_米制网格.png`：带米制网格的俯视图
- `检查视角/*.png`：人眼高度（1.6 米）的视角图，场景里站着一个 1.75 米的白色参照人，用来感受空间大小

问用户："空间结构和大小对不对？"有偏差就改 `scene.json` 重跑。

### 第 4 步：摆人物、拆分镜 → **确认③**

1. 把用户的分镜/描述整理成《分镜执行表》（格式见 [templates/分镜模板.md](templates/分镜模板.md)）：每镜的时间、景别、焦段、机位、运镜、人物在做什么。用户给的是自然语言时，先按 [运镜与剪辑规则](references/运镜与剪辑规则.md) 补全，并说明你的选择。
2. 写 `blocking.json`，运行 `blocking`。输出：
   - `俯视走位预览.mp4`：俯视的动态调度预览。人物圆点按时间移动，带朝向箭头、轨迹、名字和姿态，左上角是时间码
   - `俯视走位图.png`：整段走位的静态总图（起点、终点、每个关键时刻的位置和朝向）
   - `检查报告.md`：走速、穿墙、人物重叠
3. 自己先看一遍，再把分镜执行表、俯视走位预览、俯视走位图一起给用户确认。

### 第 5 步：低清预览，反复修改

写 `shots.json`，运行 `preview`。然后：

1. 读 `检查报告.md`。**"警告"全部要处理**：改参数，或者确认是故意的并告诉用户。"提示"酌情处理。
2. 看 `联系表.png`（每 0.5 秒一张缩略图）和 `俯视走位图.png`（带每个镜头的相机位置和视野）。
3. 自查没问题后给用户看：
   - `对照预览.mp4`：左边是俯视调度（黄色扇形 = 当前镜头的相机和视野），右边是镜头画面，同步播放。**最适合用户检查调度和运镜**
   - `预览_低清.mp4`：纯镜头画面
   - `联系表.png`、`镜头参数表.md`

   然后问用户哪里要改。
4. 用户提修改意见 → 改参数表 → 重新 `preview`（加 `--tag` 写清改了什么）。

### 第 6 步：正式导出

用户满意后运行 `final`。用户需要时再加 `--empty`（同运镜、没有人物的空场版）和 `--per-shot`（每个镜头单独一条）。

交付时告诉用户这几个文件：`预演_完整版.mp4`（喂给 Seedance 的主文件）、`Seedance交接卡.md`（颜色和角色对照、建议的参考声明）、`镜头参数表.md`、`检查报告.md`。总长超过 30 秒时会自动拆成 `_第N段.mp4`，因为 Seedance 参考视频总长不能超过 30 秒。

## 与用户沟通

- 用白话。专业词第一次出现时加括号解释，比如"轴线（两人之间的假想连线，相机不要越过它）"。
- 每次出图、出视频，说清楚：这一版改了什么、自动检查还剩什么问题、需要用户确认什么。
- 自动检查和自查都不能代替用户确认。没让用户看过的版本，不要说"已确认"。
- 不确定的尺寸、动作理解、镜头意图，直接问用户，不要猜。

## Blender 窗口和 MCP（可选）

整个流程用命令行就能走完，不依赖 MCP。

- 想让用户在 Blender 里看三维场景：运行 `open`，它会在 Blender 窗口里打开最新版本的 `工程.blend`。
- 如果当前 Agent 接了 Blender MCP（比如社区版 mcp-for-blender），可以用它截取视口图，或读取用户在窗口里手动拖动过的物体位置。**读到的新位置必须写回参数表**，再重新生成，否则下次生成就丢了。安装与配置见 [references/安装与MCP.md](references/安装与MCP.md)。
- 人物和相机的动画是逐帧烘焙的，用户在窗口里拖人物或相机只会改到当前那一帧。让用户用文字描述要怎么改，由你来改参数表。

## 文件边界

- 项目文件（参数表、输出版本）都放在**用户的项目目录**里。技能目录只读，不往里面写项目内容。
- 用户给的原始图片只复制，不修改。
- 不覆盖已有版本；不关闭用户正在用的 Blender 窗口。

## 和总调度的配合

本 skill 可以单独用，也会被同插件的总调度 `film-pipeline` 调用。

- **项目模式**：能找到这场的 `进度表.md`（在当前文件夹、上一级，或往下两层的 `作品/集场/` 里）、这一步又不是 film-pipeline 交过来的时（交过来的交接说明以「项目模式（总调度交过来）」开头），先加载总调度 `film-pipeline`（Claude Code 里是 `/shanggu-film-pipeline-fqllg:film-pipeline`，Codex 里是 `$film-pipeline`），按它的规则做；做完由它存文件、更新进度表，并用白话告诉用户存在哪、进度表改了哪一条。灰模项目文件夹就是这场的 `02_预演/`，`init` 时指定这里。
- 交给提示词和画布的只用名字带 `_final` 的最新版本（`预演_完整版.mp4`、`Seedance交接卡.md`、`镜头参数表.md`）；preview 版只给人看。
- **按条切段由本 skill 做**：提示词定好拆条后，每条切一段只含这一条镜头、时长一致的灰模视频，存成 `02_预演/按条参考/第N条.mp4`，**每段不少于 4 秒**（见插件 `shared/Seedance平台.md`）。最新 `_final` 里没有 `分镜头/` 时，先问用户要不要加 `--per-shot` 重出一版；也可以用 FFmpeg 按时间裁。切好后报告每段时长、是否都不少于 4 秒，并提醒：每段从 0 秒算，提示词时间轴照这一段写，不照完整版的时间码。
