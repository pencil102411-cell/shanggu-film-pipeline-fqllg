# 上古影视工作流 · 总调度

## 管什么、不管什么

本 skill 只做三件事：

1. **判断这一步交给谁**（见「分派表」）。
2. **在项目模式下记进度表**（见「进度表」）。
3. **规定每一步交接时留下什么文件、下一步读什么**（见「交接」）。

具体工作全部交给同一插件里的 5 个 skill。各 skill 的规则在自己的领域里照用；和本文件说法不一样时，取更谨慎的那条（多一步确认、少花积分、不动用户的文件）。用户亲自定的这几条，任何 skill 都照做：灰模默认不做；局部修改和换机位只在用户明确要求时用；生成结果先问用户看片感受，用户说不清或让 AI 看时再抽帧；「继续」不等于同意花积分。

| skill | 负责 |
|---|---|
| `blender-greybox-previs` | 灰模预演视频，以及按条切灰模参考视频 |
| `horizontal-cinematic-prompt-agent-v2` | 写、检查、返修 Seedance 生成提示词；场次记忆 |
| `xuanshang-canvas` | 上传认证素材、建视频节点、提交生成、转成片、查进度 |
| `video-local-edit` | 在用户手上已有的视频上做局部修改（只在用户明确要求时用） |
| `video-rephotography` | 保留已有视频的表演、换机位重拍（只在用户明确要求时用） |

几个 skill 共用的平台知识在插件根目录的 shared 文件夹（路径写作 `<技能目录>/../../shared/…`）：平台能力和上限 `Seedance平台.md`、素材引用写法 `素材引用写法.md`、信息来源标注 `信息来源标注.md`。

## 两种用法

- **单次**：没开项目，用户只要某一步的结果。直接交给对应 skill，不建文件夹、不记进度。
- **项目模式**：用户明确说"开这一场""这场从头做""建个项目""帮我记进度"之类的话，才建项目文件夹和进度表。

**找进度表**（判断是不是项目模式）：先看当前文件夹和上一级；没有就看当前文件夹往下两层（`作品/集场/进度表.md`）。找到一份就用它；找到几份就问用户做哪一场；用户说"接着做 E03-S012"时，按集场名找。找到后先读它，不重新建。用户只说"接着做 某场"或问"做到哪了"时，按「每一步做完」里「只问进度」那条只报告状态和建议的下一步，等用户点名下一步再做。

开项目时：

- 问两件事（已经知道的不重复问）：
  - **画布项目**：一场一个画布项目。已经建好了就记下名字；没建就建议名字「作品-场次」（例如 `风起玲珑骨-E03-S012`），用户确认后再建。
  - **场次记忆**：要不要同时建（记这场的创作要求和前后接戏的状态）。建的话放在进度表同一个文件夹。问的时候两个选项都不标推荐，只说清：建了以后你说"记住……"才会记；不建也不影响写提示词。
- 文件夹里已有分镜表的，写进度表和场次记忆之前，先只读分镜里的场景、日夜、内外景几列；读不了就写"待按分镜核对"，不先照剧本填。
- 建好后告诉用户：「项目在 `…\E03-S012\`。以后接着做，在同一个文件夹（或它的上一级）开会话，说"接着做 E03-S012"就行。」

项目开着时，用户直接说某一步的需求（"把第3条写成提示词""第5条生成好了吗"），也先经过本调度：查进度表弄清"第N条"是哪个文件、哪个节点，交给对应 skill，做完更新进度表。其他 skill 被单独叫出来、又发现了这场的进度表时，会先加载本调度再做。

## 分派表

| 用户手里有什么 / 想要什么 | 交给 |
|---|---|
| 有分镜表或分镜要求，要出视频提示词 | `horizontal-cinematic-prompt-agent-v2` |
| 要灰模、预演、走位参考视频 | `blender-greybox-previs`，做完再交给提示词 |
| 提示词拆条定了，这场做过灰模，要按条切灰模参考视频 | `blender-greybox-previs`（见「交接」里的「灰模按条切段」） |
| 要传素材、建节点 | `xuanshang-canvas` |
| 要提交生成、转成片 | `xuanshang-canvas`（用户明确说了才做） |
| 问进度 | `xuanshang-canvas` 查，本调度记进度表 |
| 生成结果不满意，要换提示词重新生成，或在原提示词上改 | `horizontal-cinematic-prompt-agent-v2` 返修，再回画布 |
| 明确要在已有视频上改某处（给了视频，或说"在这条视频上改/换掉/去掉……"） | `video-local-edit` |
| 明确要保留已有视频的表演、换机位重拍或补拍角度 | `video-rephotography` |
| 不满意的是局部修改或换机位的结果 | 交回做这次修改的 skill 改编辑提示词；用户说放弃修改、重新生成时，才回提示词 skill |
| 只要分镜方案，或者手里还没有分镜 | 不在本插件里做。说明需要先有分镜（可以用单独的分镜工具），有了再来 |
| 人物、场景设定图的图像提示词 | 不在本插件里做 |

## 这场要不要灰模

- **默认不做**：直接按用户的分镜表或分镜要求写提示词。
- **用户说要灰模、预演、走位参考视频**：先做灰模，再写提示词。
- **用户没说，但这场走位复杂**（多人同时移动、站位和空间位置要精确、几个镜头之间站位要接上），或者**没做灰模、走位反复生成不对**：提一句"这场可以先做灰模锁住走位，要不要做？"，由用户决定。用户说不用或没回应，就照常写提示词。不自己开做灰模。

## 每一步做完：停下、给看、等点头

- **"一步"指分派表的一行**，比如"写第1–4条提示词"。画布那几行里，传素材建节点、提交生成、转成片各算一步。步骤里面不逐条停。
- 每一步交付后停下，收尾说三件事：**出了什么**（文件路径）、**下一步建议**、**需要你确认什么**。提示词这一步，这三件事放在「本轮读取清单」前面，清单仍是整条回复的最后一项。
- 子 skill 自己规定的停点照停：灰模的三道确认、换机位第一轮先要参考图、画布新建认证分组前先问名字。
- 不连着跑：用户说"继续"或点名下一步，才交给下一个 skill。
- **用户只问进度（"做到哪了""第N条怎么样了"），或只说"接着做 某场"时，只读、只报告**：可以查进度表、去画布核对实际状态，但不写接线单、不改提示词、不建节点。"接着做"只是告诉你做哪一场，不算同意做下一步。画布查到的新事实（任务完成、样片日期、输出文件路径）照「生成结果出来以后」第 1 条直接记进进度表，并告诉用户改了哪一条；进度表和画布矛盾时（例如记着有节点、画布上没有）才停下问用户以哪个为准。
- **"继续"不等于同意花积分**。提交生成、转成片，必须用户明确说"生成第几条""转成片"才做。
- **用户说"生成第N条"，可这一条还没建节点**：先按接线单建好，把画布工具返回的「参数」「保存核对」「引用格式检查」念给用户，停下，等用户再说一次"生成"。
- 子 skill 规定必须告诉用户的内容（提示词的「本轮读取清单」、画布的「保存核对」「引用格式检查」「存储去向」「参数」、灰模检查报告里的警告），原样转告，不因为在总调度里就省略。

## 交接：每一步留下什么、下一步读什么

| 步骤 | 留下的文件 | 下一步怎么用 |
|---|---|---|
| 灰模 | 灰模的项目文件夹就是 `02_预演/`（初始化时指定这里）。只用名字带 `_final` 的最新版本：`02_预演/output/vNN_final_说明/` 里的 `预演_完整版.mp4`（超过 30 秒时是 `预演_完整版_第N段.mp4`）、`Seedance交接卡.md`、`镜头参数表.md`、`检查报告.md`。preview 版只给人看，不交给画布 | 提示词 skill：交接卡里的"颜色 ↔ 角色"和建议的参考声明用进【素材引用】；镜头参数表的时长、焦段、机位、运镜作为依据。剧情、表演、台词仍以 `01_分镜/` 原件为准 |
| 灰模按条切段 | 由 `blender-greybox-previs` 做：提示词拆条定了以后交回给它，每条切一段只含这一条镜头、时长一致的灰模视频，存成 `02_预演/按条参考/第N条.mp4`，**每段不少于 4 秒**。最新 `_final` 里没有 `分镜头/` 时，先问用户要不要加 `--per-shot` 重出一版；也可以用 FFmpeg 按时间裁。切好后报告每段时长、是否都不少于 4 秒 | 画布：作为这一条的参考视频上传认证。每段从 0 秒算，提示词时间轴照这一段写，不照完整版的时间码 |
| 提示词 | 由总调度把提示词代码块原样存成 `03_提示词/第N条_vN.md`，代码块外的假设、拆点一起存；「本轮读取清单」不存进文件 | 【素材引用】就是这一条的素材清单，画布照它的编号填接线单 |
| 素材上画布 | 新素材记进这场的 `04_素材表.md`；这一版的接线单存成 `04_接线单/第N条_vN.md`，版本号和提示词一致 | 建节点时照接线单接线 |
| 建节点、生成 | 进度表记：节点名（以画布工具返回的为准）、每次提交的任务 ID、样片出来的日期、查进度拿到的输出文件 | 返修提示词时对照；用户明确要局部修改或换机位时当母版 |
| 局部修改 / 换机位（仅用户明确要求时） | `05_修改/第N条_修改NN.md`：母版（画布节点名或文件）、变更单或机位表、提示词、这次的接线单（(视频1) = 母版节点，(图片N) = 新参考图） | 回画布建新节点；进度表这一条的「修改」里记一行 |

文件规矩：

- 每次都新建版本，旧版本不覆盖：提示词和接线单 `_v1`、`_v2`……；修改 `_修改01`、`_修改02`……。
- 用户给的原始文件只复制进项目文件夹，不修改。
- 参考图默认照原图分辨率上传，不先缩小（用户决定）。
- 提示词文件开头只写条号、版本、来源镜号；画布参数只写在接线单里；一个文件只放一个代码块。

**交给子 skill 时，交接说明（调用 skill 时附带的 args）固定这样写**，子 skill 看到这个开头就知道是本调度交过来的，不再重复加载本调度：

`项目模式（总调度交过来）｜集场｜项目文件夹｜这一步（分派表哪一行）｜要读：进度表、03_提示词/第N条_vN.md、04_接线单/第N条_vN.md（还没有的写"还没有，本步写"）｜用户原话｜不做：提交生成、转成片（用户明确说了的除外）`

各表格的样式见 [templates/](templates/) 下的 `进度表模板.md`、`素材表模板.md`、`接线单模板.md`。

### 灰模和提示词谁说了算

- 灰模定稿版是这场最新的镜头设计：时长、焦段、机位、运镜以它为准。
- 用户这一轮又要改运镜时，以用户为准，同时指出和灰模不一致，问是改灰模还是只改提示词。
- 镜头参数表里的时间带小数，提示词和画布都只用整数秒：提示词按就近整秒写，并在代码块外注明。做灰模时尽量把切镜点放在整秒上。

## 素材编号：每条视频各自从 1 开始

**同一个素材，在不同的条里编号可能不一样。** 图片、视频各自从 1 开始，按这一条接入的顺序编号：第1条的 (图片1) 是角色A；第2条如果先出场的是角色B，(图片1) 就是角色B。画布按建节点时给的素材顺序编号：第一个接入的图片节点就是 (图片1)。完整规则见 `<技能目录>/../../shared/素材引用写法.md`。

所以分两张表：

- **素材表**（每场一份，`04_素材表.md`）：每个素材一行，不写编号。认证素材和认证分组都跟着画布项目走，每个画布项目各有各的；一场一个画布项目，所以换一场要在新项目里重新上传认证，素材表里记着本地原文件，下一场照着找文件再传。认证分组建了删不掉，新建前先问名字（可以建议用和画布项目一样的名字）。
- **接线单**（每条视频每一版一份，`04_接线单/第N条_vN.md`）：按这一版提示词里的编号写，只接这一条用到的素材。

建节点前，用白话把接线单念给用户确认，例如"(图片1) = 角色A 正面，(视频1) = 灰模第1条"。

### 要上玄上画布的提示词，写之前先告诉提示词 skill 这几点

项目模式下，这场每条默认都要上玄上画布：

- **不用参考音频**：画布第一版不支持音频。人物音色、环境声改成文字描述。
- **关键帧逐张写出**：「以(图片1)、(图片2)、(图片3)的顺序作为关键帧」，不写「至」。
- **正文里提到参考视频也写 (视频1)**，不写「参考视频」后面直接跟数字。
- **不留 `@角色名` 这类占位**：上画布前必须换成 (图片N)。

已经写好的提示词有上面这些情况时，交回提示词 skill 局部返修、出新版本，再建节点。只有编号顺序对不上时，才调整接线顺序。

## 建节点时的参数

画布工具有默认值（5 秒、21:9、多模态参考、样片、种子 1）。不按这一条的实际情况传参，就会出错，比如提示词写了 15 秒，只出 5 秒。

| 参数 | 怎么定 |
|---|---|
| 模式 | 普通生成：多模态参考（`multimodal`）<br>首帧：首帧生视频（`first-frame`），只能接 1 张图<br>首尾帧：首尾帧生视频（`first-last-frame`），只能接 2 张图<br>延长：视频延长（`video-extend`），要延长的视频直接接画布上那一条的节点<br>局部修改、换机位：视频编辑（`video-edit`） |
| 时长 | 视频编辑不传（只能跟着原视频）；其他模式填这条提示词时间轴的最后一秒（整数，4–30） |
| 比例 | 多模态参考：用户或项目定的，没定就 21:9。其他四种模式不传（画布只能用"自适应"），所以首帧、首尾帧的图本身就要做成目标画幅 |
| 分辨率 | 默认样片（`draft`） |
| 种子 | 默认 1。同一条提示词想"再抽一次"，要换种子并新建节点，先问用户 |
| 节点名 | `第N条-vN`（和提示词版本一致）；同一版换种子再抽时用 `第N条-vN-种子M`；修改用 `第N条-修改NN`。画布遇到重名会自动加 `-v2`，以工具返回的为准 |

建好后，把画布工具返回的「参数」那一行念给用户核对。

## 生成结果出来以后

1. 用户说生成好了或问进度：交给画布 skill 查（`get_task`），把输出文件记进进度表。工具返回的有时只是相对路径，先确认文件在电脑上真的存在。
2. 问用户看片的感觉。用户描述不清，或者请你看时，用 FFmpeg 抽几帧来看，并按 `<技能目录>/../../shared/信息来源标注.md` 写清哪些是你看到的、哪些是用户说的。没看就不说"看过了"。
3. 按用户的要求走：

| 情况 | 交给 |
|---|---|
| 满意 | 用户说转成片时，画布 skill 转成片。样片超过 7 天就不能转成片，进度表里记着样片日期，快到期时提醒 |
| **不满意（默认路线）**：换提示词重新生成，或在原提示词上改 | 提示词 skill 按生成结果返修，再回画布 |
| 走位或空间整体错，而且这场做了灰模 | 先改灰模参数重出预演，再返修提示词 |
| 用户**明确**要在这条视频上局部改（"在这条视频上把……换掉/去掉"，或直接给了视频要求改某处） | `video-local-edit` |
| 用户**明确**要保留这条视频的表演、换机位重拍或补拍角度 | `video-rephotography` |
| 不满意的是局部修改或换机位的结果 | 交回做这次修改的 skill；用户说放弃修改、重新生成时，才回提示词 skill |

**`video-local-edit` 和 `video-rephotography` 只在用户明确要求、在已有视频素材上动手时才用。** 用户只说"手穿模了""表情不对""重新来一条""效果不理想"，都走默认路线：返修提示词、重新生成（局部修改、换机位自己的结果除外，见上表）。不主动把问题转成视频编辑或重拍，也不主动推荐这两条路线。

### 用了局部修改或换机位之后

- 母版（要在上面改的那条视频）：用户给了文件就用用户给的；用户只说"这条"，就用进度表里记的那次输出，并跟用户确认是哪个文件。
- 母版是画布上生成的，就直接把那个节点接成 (视频1)，不要下载再上传，也不做转码、调帧数的预处理。
- 换机位第一轮只交"要补哪些参考图"的清单，然后停下等用户给图。新参考图照原图上传认证后，记进素材表。
- 回画布建节点时，模式用视频编辑（`video-edit`），照 `05_修改/` 里那份接线单接线。
- 拼接、回贴出来的成品是本地文件，进度表里注明"本地拼接"。

## 进度表

一条视频（一次生成）占一条记录，不是一个镜头。提示词 skill 会把时间连续、总长不超过 30 秒的几个镜头合成一条，所以要写这一条包含哪几个镜头。样式见 `templates/进度表模板.md`。

- 表头记：作品、集场（例如 `E03-S012`）、这场的画布项目名（开着多个画布时连端口一起记）。集场只写编号；场景、日夜、内外景只写在场次记忆里，没建场次记忆才写进进度表（以分镜为准，剧本写得不一样时两种都写，注明「按分镜」）。
- 上面一张短表（条｜镜头｜状态｜下一步），一眼看清每条到哪了；下面每条一小段写细节（灰模、提示词文件、接线单、画布节点、任务、输出文件、修改、历史）。
- 状态只用这几种，按先后排：待写提示词 → 提示词已写 → 已建节点 → 已提交生成 → 已出样片 → 已通过 → 已提交转成片 → 成片已出；中途可能是：生成失败（写原因）/ 待返修提示词 / 待局部修改 / 待换机位。状态一栏只写这些名字，版本号写在「下一步」或每条细节里。

规矩：

- 每一步做完更新对应那条，并告诉用户改了哪一条，例如"第3条：样片已出，等你看"。
- 节点名照画布工具返回的记，不要自己推算。
- 同一条每次提交都记下任务 ID（按节点查进度只能查到最近一次）。
- 转成片后，另记成片的任务 ID 和节点 ID（成片节点都叫"成片生成"，不能按名字找）。
- 局部修改、换机位每做一次，在这一条的「修改」里记一行：修改NN、画布节点、任务 ID、输出文件、是否本地拼接。
- 换了新版本，旧版本挪进「历史」，写清版本号、节点名、任务 ID、输出文件、为什么换掉。不删。
- 进度表只记"文件和节点做到哪了"，不记创作要求。

## 进度表和场次记忆的分工

- **进度表**（本 skill 维护）：文件、版本、画布节点、任务、输出文件位置、状态，以及哪一版已通过。
- **场次记忆**（提示词 skill 维护，只在用户授权维护时）：本场的创作要求、人物位置和前后接戏的状态，放在进度表同一个文件夹。有进度表时，它的「做到哪里」只写一句"详见进度表"，涉及版本时只写"后面接戏以哪一版为准，文件见进度表第N条"。
- 同一件事不写两遍。

## 项目文件夹

放在用户给的路径；没给就在当前工作目录下建 `作品/集场/`。场次编号沿用提示词 skill 的写法：《风起玲珑骨》用场次索引里的编号，例如 `E03-S012`（它和剧本里的场号不一定相同，按提示词 skill 的规则换算）。

## 第一次使用：检查电脑环境

只检查用户接下来要用到的步骤，用白话报告结果。**要装任何东西，先说清装什么、多大、装到哪，用户同意了才装。**

- 要用画布：uv（画布插件运行要用的小工具）找不找得到；画布有没有开（`canvas_status`）。第一次启动画布工具要下载约 50MB 依赖。
- 要做灰模：Blender（做三维灰模的软件）、FFmpeg（处理视频的命令行工具）、Pillow（Python 处理图片的组件）。灰模 skill 的 `setup` 命令会检查。
- 要抽帧看片：FFmpeg。
- 画布工具连不上时，先按画布工具 README 的自检步骤查，照自检报的原因处理。多个会话同时用画布是正常的，不要因为连不上就让用户关其他会话；只有自检报「正被别的程序占用」或「另一个程序正在使用此文件」时才这样做。在 Codex 里连不上，还要看配置文件登记的启动小脚本 `%USERPROFILE%\.codex\shanggu-film-pipeline-fqllg\start-canvas.ps1` 在不在。
