# 深度视频重渲染

把一条已有的视频转成**深度视频**（只留下画面里各处远近层次的黑白灰视频，人物长相、服装、场景的颜色和材质都不在里面），再把它当参考视频重新生成一条：镜头和动作跟着深度视频走，人物和场景换成用户新给的参考图。

本 skill 只做前半段：转深度视频、核对能不能当参考视频、问清要换成什么、写交接卡。提示词由 `horizontal-cinematic-prompt-agent-v2` 写，上画布和生成由 `xuanshang-canvas` 做。

## 什么时候用

**只认口令**：用户说了「深度视频」「转深度」「深度重渲染」才用。

- 用户只是给了一条视频、让看视频、说哪里不对：不是这条路，按看片、返修提示词、重新生成处理。
- 用户只说"换个人物""换个场景"，没提深度：也不是这条路，不主动改走深度，也不主动推荐。
- 要在原视频上直接改一小块，是 `video-local-edit`；要保留表演换机位，是 `video-rephotography`。

## 第一步：确认原片

问清是哪个文件（已经说清的不重复问）。用户只说「这条」时，跟用户确认具体文件。原片只读，不改、不覆盖、不挪走。

## 第二步：检查本机有没有工具

转换用的是「离线深度视频」（一个不联网的小工具，自带模型和 FFmpeg）。所有操作都走本 skill 的脚本，在普通 PowerShell 窗口运行，不用管理员：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<技能目录>\scripts\depth-tool.ps1" check
```

- 报「已安装」：直接用，不重复安装。脚本会按这个顺序找：上次记住的位置、本插件安装的位置、系统里的安装登记、桌面和开始菜单的快捷方式、常见安装位置。
- 报「未安装」（退出码 2）：
  1. 先问用户是不是已经装在别处。是的话运行 `check -ToolDir <工具所在文件夹>`，脚本会记住这个位置。
  2. 确实没有，运行 `install`（不加 `-Yes`）。这一步只打印要装什么、下载多大、装好后占多少、装到哪，不会动手。
  3. 把这些原样告诉用户，**用户同意后**才运行 `install -Yes`。下载约 370 MB，装好后约 870 MB，默认装到用户文件夹下的 `.shanggu-film-pipeline-fqllg\offline-video-depth`，只是解压，不写注册表；不要了直接删掉这个文件夹。
  4. 用户手上有别人拷来的安装压缩包时，用 `install -Yes -PackagePath <压缩包>`，不下载。
- 安装报错时，把脚本的报错原样告诉用户，不自己改去别处下载。

工具只支持 Windows。

## 第三步：看时长，定转哪一段

平台对参考视频的要求见 `<技能目录>/../../shared/Seedance平台.md`「一、能力和上限」：单段 4–30 秒，一次生成里所有视频加起来不超过 30 秒。

- 原片不超过 30 秒：整条转。
- 原片超过 30 秒：问用户用哪一段（从第几秒到第几秒），不自己定。
- 原片或选的那段不足 4 秒：告诉用户这一段不能单独当参考视频，由用户决定换一段还是放弃。

## 第四步：转深度视频

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<技能目录>\scripts\depth-tool.ps1" convert -Video "<原片>" -Output "<输出.mp4>" [-Start <从第几秒> -Seconds <转多少秒>]
```

- 默认黑白灰度。用户要别的样式时加 `-Colormap`（可选 turbo、magma、viridis、plasma、inferno、jet）。
- 输出文件已存在时脚本会拒绝，换个文件名（序号加一），不覆盖旧的。
- 没指定 `-Output` 时，存在原片旁边，文件名是原片名加 `_深度`。
- 转换只用处理器、不用显卡，比较慢。开始前把脚本打印的「预计耗时」告诉用户。一台电脑上实测每秒处理约 1.4 帧（1470×630），10 秒的片约 3 分钟、30 秒约 9 分钟，电脑不同差别很大。预计超过两分钟时放到后台跑，跑完再继续。
- 转完脚本会打印深度视频的时长、尺寸、帧率、大小，和「对照平台要求」的结论。**原样转告用户**。写着「不符合」时停下，说明哪一项不符合，由用户决定怎么办。

转出来的深度视频：尺寸、帧率和原片一样，**没有声音**。旁边会多一个同名的 `.json`，记着帧数、帧率、尺寸、时长，留着不删。

## 第五步：让用户看一眼

把深度视频的路径给用户，请用户打开看一下人物和空间的轮廓是否清楚。用户让你看时，用 FFmpeg 抽几帧来看，并按 `<技能目录>/../../shared/信息来源标注.md` 写清哪些是你看到的。没看就不说"看过了"。

## 第六步：问清要换成什么

列一张清单，向用户要图（已经给了的不重复要）：

- **人物**：原片里每个要换的人物，换成谁、用哪张参考图。原片里的人物用位置和出场先后来指认（例如"开头站在画面左边的那个人"），由用户确认对应关系。
- **场景**：换成什么场景、用哪张参考图。
- **不换的部分**：用户说要保留的（例如只换人物、场景不动），记下来。场景不换时，也需要一张场景参考图，因为深度视频里没有原来场景的颜色和材质。
- **台词和声音**：深度视频没有声音，原片的台词和声音不会带过去。新的一条要不要台词、说什么，由用户定，记进交接卡，交给提示词 skill 写。

人物、场景具体怎么写，是提示词 skill 的事，本 skill 不写。

## 第七步：写交接卡

照 [references/交接卡模板.md](references/交接卡模板.md) 填一份，和深度视频放在一起（同名，扩展名 `.md`）。交接卡是给提示词 skill 和画布 skill 看的，里面有：原片和深度视频的事实、人物和场景的对应关系、建议的参考声明、上画布的接法。

**建议的参考声明还没有实测过**，是仿照灰模参考视频的写法写的。交接卡里照模板保留「未实测」的标注；用户出片后说效果不对时，按用户的反馈改，并把改后的写法告诉用户。

## 交给下一步

停下，告诉用户：深度视频和交接卡在哪、下一步建议（写提示词）、需要确认什么。用户说继续，才交给提示词 skill。

下一步各 skill 要知道的事（都写在交接卡里）：

- **提示词**（`horizontal-cinematic-prompt-agent-v2`）：照常按五区块写。这是参考生视频，不写任务类型那一句；提示词里不出现「修改、替换、增加、删除、延长、延续、续写」这些词（见 `<技能目录>/../../shared/Seedance平台.md`「二、任务类型和第一句怎么写」），新人物、新场景直接照参考图描述，不写"把谁替换成谁"。时间轴照深度视频的时长写，从 0 秒算。
- **画布**（`xuanshang-canvas`）：深度视频是本地文件，先上传认证，再接成参考视频；模式用多模态参考（`multimodal`）；时长填深度视频的时长（整数秒）。默认只接深度视频，不接原片（原片里带着原来的人物和场景）；用户另有要求时照用户的。

## 不承诺什么

- 不承诺新的一条和原片逐帧一致。深度视频只是参考，生成结果要实际出片后才能判断。
- 没有实际生成并检查过的，不报告"效果已验证"。

## 和总调度的配合

本 skill 可以单独用，也会被同插件的总调度 `film-pipeline` 调用。它只在用户点名说了「深度视频」「转深度」「深度重渲染」时才交过来。

- **项目模式**：能找到这场的 `进度表.md`（在当前文件夹、上一级，或往下两层以内的 `集场/`、`作品/集场/` 里）、这一步又不是 film-pipeline 交过来的时（交过来的交接说明以「项目模式（总调度交过来）」开头），先加载总调度 `film-pipeline`（Claude Code 里是 `/shanggu-film-pipeline-fqllg:film-pipeline`，Codex 里是 `$film-pipeline`），按它的规则做；做完由它存文件、更新进度表，并用白话告诉用户存在哪、进度表改了哪一条。
- 用户只说「这条」时，原片默认用进度表里记的那次输出文件，并跟用户确认是哪个文件。
- 深度视频和交接卡存进这场的 `06_深度/`：`第N条_深度NN.mp4` 和 `第N条_深度NN.md`（NN 从 01 起，每转一次加一，旧的不覆盖）。转换时用 `-Output` 直接指到这里。
- 用户给的新人物、新场景参考图，照原图上传认证后记进这场的素材表（`04_素材表.md`）。
- 提示词、接线单照常存在 `03_提示词/`、`04_接线单/`，接线单里写清 (视频1) = 哪一份深度视频。
- 用户对重新生成的结果不满意时，回提示词 skill 返修；要换一段或换样式重转深度视频时，才回本 skill。
