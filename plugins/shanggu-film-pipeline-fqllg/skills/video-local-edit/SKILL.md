# 已生成镜头局部修改

把待编辑的镜头当作唯一母版：只改变更单上写明的对象、区域、时段或声音类别，其余全部照母版保留。改动越小、边界越清楚，模型就越不容易把“编辑”做成“重拍”。

## 适用范围与交付

- **典型任务：** 修生成瑕疵（多余人物、乱码文字、手和道具出错、眼睛发光、服装走样）、按角色或道具参考图统一跨镜头连续性、换角色造型或长相、替换主体或道具、换背景/时段/天气/光线、局部风格化、在时间窗内加事件或特效、声音编辑（去 BGM、改台词、翻译并改口型）。
- **默认交付：** 母版记录、变更单、提交设置、处理好的参考图（写明 `(图片N)` 对应哪个文件）、可复制的编辑提示词（拆成多次时按顺序编号），以及验收点。
- **先判断可行性。** 动手前对照 [field-notes.md](references/field-notes.md)：
  - 实测成功率较高：服装、发型、首饰替换；人物身后小面积、有前景框住的换背景；时间窗较长的表演修改。
  - 实测容易失败或被重拍：正脸特写换长相；背景占画面大半的中景、远景换背景；2 秒左右短镜头里的表演修改。
  - 遇到后一类，先告诉用户风险，并给出退路：拆开提交、后期合成、重新生成。
- **改走其他路线的情况：** 整体换机位且锁住表演，用 video-rephotography；改画幅，用参考生成（官方说明编辑改画幅效果差）；续写，用延长任务；变速、裁剪、重排，在剪辑软件里做；改动大到动作和构图都得重来，直接重新生成。
- **改表演就是解除锁定。** 逐项写明解除了哪些锁、在哪个时间窗；与解除项冲突的“其余表演完全不变”不再承诺。
- **语言：** 默认中文解释，提示词也用中文，与火山方舟官方编辑模板一致。素材引用统一写成 `(视频1)`、`(图片N)`，规则和换入口时的写法见 `<技能目录>/../../shared/素材引用写法.md`（插件根目录下的 shared 文件夹）。用户使用英文入口或要求英文时给英文版，以 `Edit @Video1:` 开头。
- **边界：** 本 skill 负责分析、提示词、素材预处理和后期建议，不默认提交付费生成、上传素材或发布视频。不用于去除 AI 生成标识或他人水印。

## 先确定母版

母版就是本次要提交编辑的那个文件。记录：文件标识、来源模型（Seedance 2.5 / 2.0 / 其他）、时长、帧数与帧率、画幅与分辨率、容器与编码、音轨状态、片内切点。

- **选哪个文件：** 优先用剪辑前的完整生成原文件（带手柄），不用成片里裁短、加过字幕、调过色或转过码的版本。
- **平台硬约束**（编辑任务的细节见 [platform-notes.md](references/platform-notes.md)，通用的能力和上限见 `<技能目录>/../../shared/Seedance平台.md`）：
  - 待编辑视频 4–30 秒，20 秒以内更稳。
  - 输出画幅和时长继承母版，不能另设。
  - 把帧数调成 8n+1，可以减少输出时长的偏差。
  - 编辑和链式编辑都建议用 mov。
- **输出帧数不一定等于母版。** 实测既有变长（119 → 121 帧，切点提前 1 帧），也有明显变短。每次拼接或回贴前，都要实测输出的帧数和切点。
- **用户可能直接提交了原文件，** 而不是你准备的 8n+1 mov。验收时先确认实际用的是哪个母版。
- **时长不合适时：**
  - 短于 4 秒：用原生成文件的手柄或相邻镜头补到 4 秒以上，提示词写明切点和只编辑哪一段，生成后再裁回。
  - 长于 20 秒：截取包含编辑窗口的一段（带手柄）去编辑，再回贴。
  - 裁剪或拼接之后，重新建立时间表。
- **写清信息来源：** 每个事实标明是实测、用户提供、估计还是未知，规则见 `<技能目录>/../../shared/信息来源标注.md`。没有视频分析能力时，不声称看过或听过；缺的信息标“待核对”。

读 [edit-sheet-and-qa.md](references/edit-sheet-and-qa.md) 建立母版记录和编辑对象时间表。只记与编辑有关的内容：编辑对象在画、被遮挡、被手持、在运动的时段，以及片内切点；涉及人物或声音时，再加上发声窗。

## 编辑契约

1. **唯一母版。** `(视频1)` 是唯一编辑母版。输入多个视频时，写明哪个是待编辑的、哪个只作参考，因为模型按提示词的意图判定待编辑视频。
2. **变更有边界。** 每一项都写清四件事：对象/区域/声音类别、时间范围（全片或整数秒窗口）、从 A 改成 B、参考素材只提供哪一部分。
3. **同一时间轴。** 输出的时刻 t 对应母版的时刻 t。不变速、不重复、不跳时、不延长，编辑窗口内外节奏一致。
4. **连带变化要写明。** 编辑对象带来的阴影、反射、遮挡、接触、环境光、声音，应随之合理变化。列出允许或要求的连带变化，此外不得扩散。
5. **保持项默认锁定。** 身份、表演、口型、视线、动作路径与时点、手与道具的接触、机位与运镜、构图、镜头切换、光线色调、对白与环境声，除变更单和连带变化外，全部继承母版。这就是 video-rephotography 的表演锁定契约，再加上摄影层一起锁定。
6. **对象恒定。** 持续在画的对象，要改就全片改，并写明全片数量。只在时间窗内改，会在窗口边界跳变；除非剧情本来就要它出现或消失，这时写清出现和消失的方式。
7. **用户授权优先。** 用户新授权的修改优先于默认锁定，解除项逐条列出。

## 拆变更单

| 编辑类型 | 写清什么 | 必须守住 |
| --- | --- | --- |
| 删除人物/物体/文字 | 被删对象的识别特征与位置；补全区域用什么填 | 补全优先用本片其他时刻可见的背景；从没出现过的区域按最小假设，不凭空加物体；被删人物的声音和影子一并去掉 |
| 替换道具/服装造型 | 原对象 → 目标对象；`(图片N)` 只取外观、结构、材质；全片数量；造型逐项写（服装、发型、发饰、耳饰、项链） | 尺寸和轮廓接近原对象；手的接触、遮挡顺序不变；画面外的部件（腰带、鞋）不强求出现，不为展示而改构图；同画面其他角色保持原色，不被参考图的颜色带偏；造型按形状写，不用会被当真的比喻（如“猫耳”） |
| 换长相 | 骨相从 A 到 B（脸型、下巴、眉形、眼型、鼻梁、唇形）；写明“换人，不是化妆”；每个机位用一张单独裁出的脸，写明哪个镜头对应哪张 | `(视频1)` 只提供表情动作和时点，不提供长相；不写“神情、表情与原片一致”；实测正脸特写很难换掉长相，要提前说明 |
| 背景替换 | 每个镜头分别写：删掉哪些旧元素、换成哪些具体物件；`(图片N)` 是按该镜头机位裁出的“要出现的东西”；只想改材质、色调时，才写“只取材质/环境色” | 人物的脸、肤色、明暗和整体调色锁定，不写“人物色调随新环境变化”；保留前景锚点和原片亮部的位置；背景占画面大半时会被重拍，先缩小面积或按镜头拆开 |
| 增加物体/特效 | 位置、出现时点和方式、与环境的交互 | 不遮挡关键表演；光影随之变化；写明是否需要新声音 |
| 光线/时段/天气/调色 | 从 A 光到 B 光，两端都写 | 人物肤色随环境光自然变化；不改造型和动作 |
| 风格化 | 目标风格；作用于全画面还是某个对象 | 构图、动作、时序不变 |
| 时间窗事件 | 整数秒窗口 + 事件锚点；窗口前后的状态 | 窗口外完全不变 |
| 改表演 | 时间窗；从哪个动作改到哪个动作；起止状态 | 列明解除项；窗口边界与原动作衔接；镜头约 2 秒以内时改动很难看出来，先提醒用户 |
| 声音编辑 | 说话人或声音类别；目标变化；其余声音是否保留 | 改台词时口型随之改；去 BGM 时保留对白、环境声和动作音效 |

以下情况更容易失败：

- 对象被手持或反复遮挡；
- 快速运动或跨越切点；
- 改动面积大（尤其是背景占画面大半的中景、远景）；
- 和口型、面部有关（尤其是正脸特写换长相）；
- 要补全大片从未出现过的区域；
- 镜头太短，改表演没有展开的时间；
- 一次叠加多种编辑。

遇到这些情况，缩小单次改动、按镜头拆开，或者考虑后期合成、重新生成。

## 准备参考素材

参考图怎么裁、怎么描述，直接决定模型迁移什么。交付时把处理好的文件放进用户目录，并写明 `(图片N)` 对应哪个文件。命令见 [platform-notes.md](references/platform-notes.md)。

- **用最清晰的原图，** 不用聊天截图。去黑边；**默认不缩小，照原图分辨率上传**（2026-10-21 用户决定，不按官方“参考图不超过输出分辨率”的建议先缩）。
- **按用途裁图。** 换造型可以用整张三视图。换长相要把每个角度的脸单独裁出来，让脸占满画面（合图里的脸太小，模型认不清长相）。参考图里人物的朝向要和镜头一致，侧脸方向相反就水平翻转。
- **换背景按机位裁。** 每个镜头裁出对应的那一块；去掉会被搬到人物前面的家具；避开自带强构图的区域（大幅帘子、居中立柱），否则模型会让机位去迁就参考图。
- **写实人脸有限制。** 火山方舟官方说明不支持写实人脸参考图，各入口的情况和例外见 `<技能目录>/../../shared/Seedance平台.md`「三、写实真人脸素材」；实测某入口能上传，但身份迁移很弱。如果是本账号的原始生成产物，就上传原文件，不上传重新编码过的副本。

## 时间与范围的写法

- **用整数秒。** Seedance 2.5 响应整数秒时间戳，窗口写“第4-7秒”，不写“4.37 秒”。要更精确的边界，就用动作事件来锚定（“从她放下杯子开始，到转身之前”），窗口留出余量，精确边界交给后期回贴。
- **窗口连续书写。** 多个窗口之间不留含糊空洞；不用时间戳控制频次（例如“一秒眨三次眼”）。
- **用“只”字限定范围：** “只处理……”，并在收尾写“除以上明确修改的对象或区域外，(视频1) 中的其他内容保持原样”。
- **保持项按类别点名，** 不复述整段画面。母版本身已经足够精确时只做指代；只有编辑区附近容易被带偏的细节才写具体，例如握着被替换杯子的手指位置。

## 写成提示词

使用 [edit-prompt-template.md](references/edit-prompt-template.md)，结构为：编辑目标 → 原视频职责 → 目标素材职责 → 编辑范围 → 连带变化 → 保持内容 → 时间线继承 → 禁止新增。删掉与本次无关的区块。

- **开头与触发词。** 提示词以“编辑(视频1)”开头，并包含编辑触发词之一：编辑视频、增加/加上、删除/去掉、修改/替换/改成。不要出现延长类触发词（向前/向后延长、延续、续写），以免任务被判成延长。英文入口用 remove / replace / relight / restyle / change 等编辑动词。
- **参考图的作用怎么写，就迁移什么。** 写“空间风格、材质、环境色”，模型只会改颜色；要换内容，就把参考图写成“要出现的具体物件”，并逐项写要删除的旧元素。
- **写进去的特征才会被迁移。** 只列妆容，就只迁移妆容；换长相要把骨相从 A 到 B 逐项写出来。
- **保持项别锁住要改的东西。** 换长相时，写“(视频1) 只提供动作，不提供长相”。换背景时，不给人物留“随新环境变色”的余地。
- **一次只做一类变更，多次编辑优先并行。**
  - 不同镜头或时间窗的修改，从同一个原母版各自提交，在切点拼接。
  - 只有同一区域需要叠加多类修改时，才链式编辑（以上一次的 mov 输出为母版），顺序为：结构 → 环境 → 风格调色 → 声音。
  - 链式每一轮都重画整帧，输出又是压缩文件，画质会一轮轮下降，用户能看出来。
  - 多镜头修改也可以先合成一条试；没成功的镜头，再用单镜头提示词从原母版重跑。
- **声音符号：** 音乐用 `()`，音效用 `<>`，台词用 `{}`，字幕用 `【】`。改台词时写成“角色台词（情绪）：{内容}”，不在台词后复述词语，以免诱发字幕。
- **字幕和 BGM。** 母版自带字幕时，“不要字幕”可能失效，先单独做一次去字幕。去 BGM 时，把音乐类同义词列全，并在开头和结尾各写一次。
- **情绪与比喻。** 涉及人物情绪的编辑，避免用强情绪词，必要时写“正常人眼，不发光”。比喻会被当成字面意思：“猫耳发髻”可能长出动物耳朵，要写成“头顶两侧用头发盘的尖角发髻”。

## 回贴与交付

编辑会重新生成整段画面，未修改的部分也只是“基本保持”，并非像素级原样。交付要求严格时：

- **时间窗回贴：** 只取编辑窗口（带手柄）替换原片，切点放在镜头切换处或动作遮挡处。
- **按镜头拼接：** 先实测每条输出的帧数和切点，各自在自己的切点处拼接；帧数不同时，不能按时间码直接对位。
- **区域合成兜底：** 背景换成了但人物仍有漂移，且机位固定时，用遮罩（如 DaVinci Resolve Magic Mask）从原片取人物、从输出取背景。
- **音轨回贴：**
  - 需要原音不变时，以原音轨为准；输出的声音变了就回贴原音，再检查口型。
  - 实测输出音轨被重采样为 32kHz，默认换回原音。
  - 用 `-c:v copy` 替换音轨时不要加 `-shortest`，否则会丢帧。
- **相邻镜头：** 某个镜头的改动（服装、道具、光线）需要全片统一时，列出受影响的相邻镜头。
- **对比视频：** 用 [scripts/make-compare.ps1](scripts/make-compare.ps1) 把母版（上）和输出（下）上下拼接、共用母版音轨，用来验收或给别人看。

## 失败后怎么修

1. **先问用户看到了什么问题；用户说不清或让你看时，再看片，然后才改提示词。** 拼接回贴前量帧数和切点不受这条限制。看片时实测输出的帧数和切点；取同一帧号，把母版和输出并排，脸和编辑区域放大对比。没看片就改提示词，只是在猜。
2. **找出被照字面执行的那一句。** 例如“只取材质” → 只改了颜色；“神情保持原片” → 长相被锁住；“随新环境变色” → 人物被重画。
3. **分清问题类型：** 措辞被误读、范围太大、参考图带偏了构图，还是平台能力的上限。
4. **从原母版重跑，只改出问题的句子，成功部分的写法不动。** 用户接受画质损失时，才在输出上链式补改。
5. **能力上限类的问题**（如正脸特写换长相、大面积换背景被重拍），改走后期合成或重新生成，不再反复改提示词。

## 默认回答形式

1. 编辑判断：适合直接编辑还是改走其他路线，附信息来源和实测风险。
2. 母版记录与变更单，含连带变化、解除项和风险。
3. 提交设置、处理好的参考图与可复制的提示词；拆成多次时按顺序编号，写明每次用哪个母版、是并行还是链式。
4. 验收点、拼接与回贴建议、尚未验证的项目。

## 和总调度的配合

本 skill 可以单独用，也会被同插件的总调度 `film-pipeline` 调用。它只在用户明确要在已有视频上修改时才交过来；只想换提示词重新生成的，归 `horizontal-cinematic-prompt-agent-v2`。

- **项目模式**：能找到这场的 `进度表.md`（在当前文件夹、上一级，或往下两层的 `作品/集场/` 里）、这一步又不是 film-pipeline 交过来的时（交过来的交接说明以「项目模式（总调度交过来）」开头），先加载总调度 `film-pipeline`（Claude Code 里是 `/shanggu-film-pipeline-fqllg:film-pipeline`，Codex 里是 `$film-pipeline`），按它的规则做；做完由它存文件、更新进度表，并用白话告诉用户存在哪、进度表改了哪一条。
- 用户只说「这条」时，母版默认用进度表里记的那次输出文件，并跟用户确认是哪个文件。
- 母版是玄上画布上生成的，回画布时直接把那个节点接成 (视频1)，模式用「视频编辑」；这时不下载再上传，也不做调帧数（8n+1）、转 mov 的预处理。新参考图照原图上传认证，记进素材表。
- 母版记录、变更单、提示词和这次的接线单（(视频1) = 母版节点，(图片N) = 新参考图）由总调度存进 `05_修改/`。
- 用户对这次局部修改的结果不满意时，仍由本 skill 看片诊断、改编辑提示词；用户说放弃修改、要重新生成时，才回提示词 skill。
