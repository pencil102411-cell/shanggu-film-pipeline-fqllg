# 原片锁定多机位重摄影

把原片当作已经发生、不能重演的事件：重新决定观众从哪里看，不重新决定演员做什么。目标是增加动作信息、情绪层次与剪辑选择，同时保住原表演。

## 适用范围与交付

- 默认交付一条覆盖原片全时长、按时间切换机位的连续成片提示词。多机位是摄影设计，不是让模型同时画出多格画面，也不是默认输出多条完整视频。
- 用户明确要求各机位独立全长版本时，分别写独立提示词，共用同一原片和事件表；提醒需要额外核对跨版本连续性，不声称它们天然逐帧一致。
- 单独的改对白、换动作、变速或续写请求，不自动启用本 skill。若用户在已经进行的重摄影任务中明确追加这类修改，遵循新指令并列明解除的锁定项；只对仍要求保留的部分沿用本方法，不再称为完整的表演锁定，也不保留与新指令冲突的“完全不变”承诺。
- 默认中文解释、中文生成提示词。用户要求英文或中英双版时再写英文，两版逐段对应。镜头数量、长度、画幅随原片和用户目标确定，不默认 13 镜、20 秒或 16:9。
- 本 skill 负责分析和提示词，不默认提交付费生成、上传素材或发布视频。只完成用户本次授权的工作。

## 先确定实际素材

需要一个时间轴母版：原视频，或用户提供的可信原片分析。已有信息足够时直接推进，只询问影响结果的缺口。

记录：素材标识、实际时长、画幅、音轨、原拍摄机位、人物的表演对象；能取得时再记录帧率/时间戳和文件哈希。裁剪、变速、替换素材后重新建立时间表，不能继续使用旧时间码。

分清“上传原片”“生成结果”“上下对照演示”“社交平台剪辑版”。演示视频的时长、字幕和拼接版式不能自动成为原片事实。不得把对照视频作为完整原片上传并要求模型自己猜哪一半是母版。

每个事实写清信息来源：实测 / 用户提供 / 估计 / 未知（规则见 `<技能目录>/../../shared/信息来源标注.md`，即插件根目录下的 shared 文件夹）。只有测过的时间才称实测；没有可用视频或音频能力时，不声称已观看、听辨或逐帧核对。先给能完成的规则与草稿，把缺失时间标为待核对。纯模板可有占位符；标为“可直接提交”的提示词不能残留占位符或矛盾时间。

读 [timeline-and-qa.md](references/timeline-and-qa.md) 建立源事件表。先记录源事实，再设计摄影；不要用新镜头要求反推演员动作。

## 表演锁定契约

1. **同一时刻。** 全长输出满足 `t_output = t_source`，保持原片播放速度。切镜只换视角，不跳时间、不重放动作、不延长停顿。源内已有的慢动作按原样保留，不再次放慢。明确裁剪区间时才使用 `t_source = t_output + source_in`，并重算所有时间码。
2. **同一表演。** 身份、身体姿态、头角度、眼神、嘴形、眨眼、微表情、手和道具的接触、动作路径及开始结束时间均跟随原片。不能为了露脸或展示动作，移手、转头、重摆道具。
3. **同一声音事件。** 每个人物分别标注发声窗口；无台词不等于嘴闭合，也不等于整条音轨静音。饮水、咀嚼、呼吸和无声张嘴遵循原片。低头、侧脸、失焦与遮挡不能触发自动停词；看不见嘴时音轨仍连续。
4. **同一视线对象。** 人物继续看原来的 A 摄影机、对手演员或物体，不追随新机位。A 机位仅在原片确实对它表演时才是视线锚点。正轴机位也只有在该时刻源视线对准它时才出现对视。环绕穿过视线轴时允许几何上自然的短暂对视，或调整摄影路径，不能让演员为避镜头改变眼神。
5. **同一场景。** 保持服装、人物数量、道具数量、布局、光源方向与软硬、曝光、白平衡和调色基准。允许视角导致的合理透视、遮挡、视差和反光变化；不要求各机位像素或阴影形状相同。
6. **允许变化的摄影层。** 机位位置/高度/角度、景别、焦段意图、构图、焦点与景深、摄影机运动，以及按源时间连续的切镜。焦段是摄影意图，未掌握画幅与距离时不称为实测镜头参数。

源事件表与摄影描述冲突时，改摄影描述。用户新授权的表演变化优先于本 skill 默认规则。

## 从动作选择机位

先找动作、信息和情绪节点，再切镜。每个镜头应说明新增可见信息或情绪作用；不要为了凑数量，每秒机械切一镜。

| 原片节点 | 可选摄影方式 | 必须守住的条件 |
| --- | --- | --- |
| 说话、停顿、细微反应 | 正轴或偏轴近景，适度较长停留 | 不额外加强表情，不把侧脸扭正 |
| 键盘、手势、拿取物品 | 手部特写、桌面低机位 | 手指、接触和动作阶段不重置 |
| 物品与人物空间关系 | 俯拍、全景 | 不重新摆放布景，关键物品可定位 |
| 抛接、挥动、转身 | 跟随主动作的单一运镜 | 锁定离手、接触、到位时点，不延长运动 |
| 饮水等主观体验 | 可选虚拟眼位 POV | 不凭空改变源头部动作，不默认添加手持晃动 |
| 咬合、呼吸、细小动作 | 局部或微距特写 | 无声动作不变成讲话 |
| 收尾、空间回收 | 稳定中全景或俯拍 | 停留到原片终点，不强制所有原片用同一种结尾 |

一镜以一个主要摄影动作组织。平移、摇摄和环绕写明方向与终点，不能穿过实体；POV 标明是虚拟眼位。新视角看不清关键动作时，调整镜头，不改动作。需要时用过渡镜头或连续运动交代跨轴，保住观众对空间的理解。

每镜记录：`起止时间｜机位/高度/方向｜景别与焦段意图｜运动｜焦点/景深｜源动作与道具状态｜嘴部可见性/发声窗口｜视线关系｜新增信息`。

对仰拍、反打、背面等新露出区域，列出“已知可见内容”和“缺少证据的区域”，交给下一步的资产清单处理。禁止把案例的“纯白天空、无人、无建筑”套在所有原片上。

## 写提示词前：机位资产清单与索取

机位表定好后、写完整提示词前，必须先做这一步。读 [asset-checklist.md](references/asset-checklist.md)，按其中的方位约定和对照表执行：

1. **逐机位推出需要什么。** 每个机位会拍到场景的哪几个面（A 面正面背景、B 面反打方向、左侧面、右侧面、顶面、底面），每个人物会露出哪个角度（正面、侧脸、背面、头顶、手部等细节），哪些道具会被拍近。场景面统一按原画面方位命名，人物自己的左右要换算。
2. **对照原片。** 原片已经清楚拍到的不要；部分拍到或完全没拍到的列入清单，分“必需”和“建议”，每项写好缺失时的处理方式。
3. **向用户索取。** 有缺口时，这一轮回答停在资产清单：用大白话说明每张图是哪个方向或角度、用在哪个镜头、要满足什么要求，请用户按编号提供或说明没有。不要先输出完整提示词。
4. **收到后绑定。** 逐张核对与原片是否一致，按平台接入顺序给每张图一个引用标签和唯一用途，回填机位表；用户没提供的面，按选定的处理方式写进提示词。

用户已经给齐所有参考时，直接绑定并说明“各机位所需参考已齐”。用户明确说不提供或不用问时，不再追问，按处理方式继续，并在交付时列出按假设处理的部分。

## 写成完整提示词

使用 [prompt-template.md](references/prompt-template.md) 的中文模板；用户要求英文或中英双版时，使用同文件的英文模板。把模板变量替换为当前素材事实，删除无关区块。保留影响画面的具体动作、微表情、光影、运镜与时间约束，不压缩成泛泛的“保持一致、电影感”。素材引用标签按当前平台格式写，全文一致。

结构为：任务契约 → 参考素材分工 → 不变项 → 发声/无台词窗口 → 视线 → 源播放速度 → 关键事件锚点 → 新露出区域 → 逐段摄影计划 → 场景/人物连续性 → 禁止新增项。

不要同时写“输出一镜到底”与多机位硬切；一条完整原表演可以被剪成多个摄影镜头。不要把“全片一个时间轴”误写成“摄影机只能拍一个长镜头”。

素材引用统一写成 `(图片N)`、`(视频N)`，规则见 `<技能目录>/../../shared/素材引用写法.md`；平台能力和各入口差异见 `<技能目录>/../../shared/Seedance平台.md`；Scenario 作者案例的设置见 [platform-notes.md](references/platform-notes.md)。提交前核实当前界面限制。具体声画保留必须在结果中验证，文字要求不构成生成保证。

## 默认回答形式

参考有缺口时分两轮。

第一轮（索取）：

1. 简短摄影判断与信息来源。
2. 源事件表和机位表；简单任务可合并，不能混淆事实与设计。
3. 机位资产清单，以及给用户的索取说明。到此为止，等用户回复。

第二轮（收到素材，或用户说明不提供后）：

1. 参考图对照：每张图的引用标签、对应的面或角度、用在哪些镜头；未提供的面及其处理方式。
2. 一个可复制的完整中文提示词块（用户要求时附英文版）；用户只要提示词时减少说明。
3. 少量与本片相关的验收点，以及尚未验证的项目。

参考已齐、或用户事先说明不提供时，合并为一轮，按第二轮的形式交付，并保留资产清单的结论。

交付前按 [timeline-and-qa.md](references/timeline-and-qa.md) 检查时间覆盖、视线、发声、动作衔接与参考资产。只有提示词时报告“文本已核对”；拿到源素材并完成测量才能报告“原片时间轴已核对”；拿到输出并检查才能报告“成片已核对”。未执行的视频生成与音轨检查不能标为通过。

需要讲解方法来源、复盘咖啡馆案例或对照原文时，读取 [scenario-case.md](references/scenario-case.md)；通常无需加载案例全文。当前项目的数据保留在当前任务中，不写进本 skill 或其他项目的长期状态。

## 和总调度的配合

本 skill 可以单独用，也会被同插件的总调度 `film-pipeline` 调用。它只在用户点名要换机位重拍或补拍角度时才交过来；给了视频但只想换提示词重新生成的，归 `horizontal-cinematic-prompt-agent-v2`。

- **项目模式**：能找到这场的 `进度表.md`（在当前文件夹、上一级，或往下两层以内的 `集场/`、`作品/集场/` 里）、这一步又不是 film-pipeline 交过来的时（交过来的交接说明以「项目模式（总调度交过来）」开头），先加载总调度 `film-pipeline`（Claude Code 里是 `/shanggu-film-pipeline-fqllg:film-pipeline`，Codex 里是 `$film-pipeline`），按它的规则做；做完由它存文件、更新进度表，并用白话告诉用户存在哪、进度表改了哪一条。
- 用户只说「这条」时，原片默认用进度表里记的那次输出文件，并跟用户确认是哪个文件。
- 原片是玄上画布上生成的，回画布时直接把那个节点接成 (视频1)，模式用「视频编辑」，不要下载再上传。
- 第一轮只交参考图清单，停下等用户给图；用户给的新参考图照原图上传认证后，记进这场的素材表（`04_素材表.md`）。
- 机位表、提示词和这次的接线单（(视频1) = 原片节点，(图片N) = 新参考图）由总调度存进 `05_修改/`。
- 用户对这次重拍的结果不满意时，仍由本 skill 改提示词；用户说放弃、要重新生成时，才回提示词 skill。
